## 背景（用户反馈，真实样本）

1. **束水攻沙笔记**（6aeaf852000000000e00ddec，PPT 渐进展示型）：几乎每页都截到了，但都截在**信息最少的位置**——渐进展示视频每次翻页/动画都是一次"画面变化"，变化刚发生时内容最空。
2. **B站 P5**（BV1CV411s7jd?p=5，人物访谈）：全是人脸帧，无信息价值，读图是浪费且报告塞脸是负体验。

## 设计（已与用户对齐，勿改）

### 模式（CLI 与 MCP）
- 不加 `--visual` = 纯音频模式：不下载视频（现状保持，README 帮助里明确这一点）。
- `--visual` / `--visual=auto`（默认）= 混合/自动：
  - 静态簇 → 按 PPT 策略处理（见下）；
  - 高动态段（切点密集）→ 段内固定间隔采样；
  - 全程先过「画面价值门控」（见下）。
- `--visual=ppt` = PPT 模式：跳过门控，全量聚簇取末，帧数上限 40（其余模式 20）。
- MCP `digest_video` 的 `visual` 参数：`false | "auto" | "ppt"`（schema/测试同步）。

### 取帧质量（frames.py 核心改动）
1. **段末采样**：每个场景切点 t 取 `t-0.5s` 帧（变化前=该稳定段信息最全状态），夹在两切点间时做边界保护。
2. **相似帧聚簇取末**：pHash 汉明距离阈值聚簇；每簇**保留最末帧**；簇数即有效页数。
3. **簇内仲裁**：末帧与簇内次末帧差异过小无意义、或疑似转场模糊（可拉大 pHash 距离比较）时回退簇内边缘密度最高帧（Sobel/ffmpeg 信号，本地零成本；实现代价高就用「与簇首差异最大帧」替代，如实记录选择）。

### 画面价值门控（vlm.py / pipeline）
1. **本地预筛**：聚簇后若 ≥80% 帧落同一簇（低视觉多样性，口播/访谈特征）→ 跳过全部 VLM 读图，meta 记 `visual_gate="low_diversity"`。
2. **VLM 探测**（多样性正常但内容存疑时可选触发）：取 2-3 帧问「内容演示型（文字/图表/操作演示）还是人物口播型」，口播型 → 停止读图，meta 记 `visual_gate="talking_head"`。成本 ~¥0.002/次。
3. **诚实降级**：两种门控命中都让报告明确写「画面以人物口播为主，未提取信息性画面」，不嵌帧。`--visual=ppt` 不受门控影响（用户显式指定优先）。

## 验收标准（三类真实样本即三种模式的验收）

1. **PPT 模式**：束水攻沙 `--visual=ppt --summarize` → 帧对应**每页内容最全状态**（人工判断：帧数≈有效页数、相邻帧内容有实质差异、与旧产物 runs/6aeaf852…/20261121-011002 对比改进明显）；报告中帧引用有效。
2. **混合/门控**：B站 P5 `--visual` → 命中低多样性或口播门控，不产帧或 ≤2 帧，报告含降级说明，VLM 花费 ≤探测级（≈¥0.005）。
3. **图文卡回归**：零语音笔记 6aa6179a `--visual` → 仍然翻案成功（画面知识点+嵌帧不回退）。
4. 合成视频单测：段末采样时刻、聚簇取末、80% 门控阈值、ppt 模式 cap=40、auto 动态段间隔采样、模式路由（CLI parse + MCP schema）。
5. `pytest` 全绿（249+ 新增）；VLM 总花费 <¥0.3；README 更新（模式说明+门控行为+纯音频=不加 flag）。

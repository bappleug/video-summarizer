## 2. 关键接口（冻结项）

```python
# asr/base.py
@dataclass
class Segment: start: float; end: float; text: str
@dataclass
class Transcript:
    segments: list[Segment]; lang: str
    engine: str            # "mlx-whisper" / "sensevoice" / "siliconflow" / "subtitle"
    source: str            # "subtitle" | "asr"
    elapsed_s: float

class Transcriber(Protocol):
    name: str
    def available() -> bool                    # 依赖+平台自检（mlx 需 arm64）
    def transcribe(wav: Path, lang="zh") -> Transcript

# 引擎选择（D-008）：auto = mlx 可用则本地，否则 cloud（需 key，无 key 明确报错指引）；
# --engine auto|mlx|cloud；本地 SenseVoice 后端退出 MVP，协议保留可回加
```

CLI 形态（与 bili 风格一致：内容 stdout、进度 stderr、退出码语义化）：

```
digest <url|BV号>                    # 一条龙：字幕优先→ASR回退→transcript（txt）
digest <url> --summarize             # + LLM 报告（默认硅基流动托管 DeepSeek-V4.1-Flash）
digest <url> --format srt|md|json    # 产物格式
digest <url> --engine auto|mlx|cloud # 本地 SenseVoice 后端已退出（D-008）
digest <url> --visual[=auto|ppt]     # 画面增强（已实现；推荐用 --type talk|slides|mixed|auto）
digest transcribe-only <url>         # 只跑转写（未实现，也无需单独做：不带 --summarize 即只出 transcript）
digest report <run目录>              # 对已有 transcript 补报告
digest login / status                # 透传 bili-subtitle 凭据体系
digest doctor                        # 环境与 key 体检（D-009，见 §5）
```

## 3. 管线主流程（pipeline.py）

```
URL → 平台识别
 → B站: view API 元信息（cid 列表，多P展开）
   → 字幕轨探测（登录态）→ 有轨 → 下载字幕 → validate 校验①
       → 通过 → Transcript(source=subtitle)
       → 无轨/校验失败② → audio.py 下载 DASH + ffmpeg → ASR 引擎(auto) → Transcript
 → 小红书: 取材模块（S4）→ 有内嵌字幕用之，否则同上回退
 → 产物落盘 runs/<bvid|note-id>/<run-id>/: transcript.{txt,srt,md,json} + meta.json
 → (--summarize) → LLM 报告 → report.md（仅 Markdown，html 未实现）
```
① 校验规则（validate.py，MVP 三条；S2 已加第 4 条：标题/简介 bigram 相关性）：时长覆盖率（字幕总时长 ≥ 视频时长 60%）、语言一致性（中文字符占比）、重复率（连续重复行 <30%）——任一不过即视为「疑似污染字幕」，记 warning 并走 ASR。
② 校验失败**降级而不是报错**——这是对风控污染的核心防御姿势。

## 5. 设计原则与硬约束回顾

- **零 key 可用（D-010 后收窄）**：只在装了 `[mlx]` 的 Apple Silicon 上成立（字幕 + 本地 ASR 全链路零 key）；其余设备/未装 mlx 时无字幕视频需免费硅基流动 key 走云端转写。key 影响 summarize、cloud 与读图。
- **双端 Mac（D-008 后）**：AS 机器本地 mlx（零 key 可用）；Intel 机器装包即用云端（仅依赖免费硅基流动 key），无需任何模型文件。
- **引擎默认（D-010）**：**云端是保底主路线**（所有设备一致）；本地 mlx 是可选插件——`auto` 规则：本地后端可用且已装 → 用本地，否则云端。不强制任何设备装模型。
- **Key 体验（D-009）**：`digest doctor` 体检三把 key（实测 ping 一条极短消息验有效性、查余额接口、硅基流动自动试 `.cn`）+ 本地依赖（mlx/ffmpeg）+ 登录态，输出「能力×状态×下一步动作」表格。运行时错误分类映射：401→key 无效或端点错（附注册/控制台 URL）、402→余额不足（附充值入口）、403→实名/权限、429→限流稍后重试、超时→网络。所有涉及 key 的失败必须给「去哪检查、怎么修」，不允许裸抛错误码。
- **网络现实**：HF_ENDPOINT 默认 hf-mirror.com 写进 config.py；模型目录可配、可复用现有 `runs/asr-bench/models/`；PyPI 直连慢，开发装包用 `UV_INDEX_URL=https://pypi.tuna.tsinghua.edu.cn/simple`（写入 README 开发节）。
- **成本可见**：每次 summarize 在 meta.json 记录 usage（tokens/估算成本）。
- **stdlib 优先**：核心管线（字幕/下载/编排/CLI）不依赖第三方包；ASR/LLM 按需 extra。

## 6. 实施顺序（Phase 3 冲刺，每个都有验收标准）

| 冲刺 | 内容 | 验收 |
|---|---|---|
| S1 | B站 transcript 管线：bilibili 模块迁移 + audio + mlx 引擎 + validate + CLI | 有字幕视频走字幕；无字幕 P5 mlx 出 transcript；污染字幕被拦截并降级；格式与 bili fetch 对齐 |
| S2 | summarize（GLM 默认/DeepSeek 备+模板+report，**独立组件形态**）+ **cloud_sf 云引擎** + **digest doctor**（key 体检与错误指引）+ 组件归位重构（asr/→transcribe/）+ **validate 规则 4：标题相关性**（S1 实战暴露的「完整无关字幕」缺口） | P5 生成中文报告，成本记录在 meta.json；--engine cloud 出 transcript 与本地等价；doctor 对好/坏 key 输出正确诊断；两个组件可脱离壳工程独立 import 使用；构造完整无关字幕样本被规则 4 拦截 |
| S3 | MCP server：5 工具（digest_video / job_status / get_transcript / get_report / cancel） | 豆包类客户端可发现并调用；stdout 污染防护照抄 BTC |
| S4 | 小红书：VRA 取材模块接入管线 | 小红书视频笔记出 transcript（需 cookie 场景文档化） |
| S5 | SQLite 历史 + 批量队列 | 历史可检索；批量含风控退避 |
| S6 | 视觉增强 `enrich` 组件：ffmpeg scene 检测 + pHash 去重 + 帧数上限（≤20、最小间隔 5s，无切换退化为均匀采样）→ VLM 批量读图（带时间戳；默认硅基流动 Qwen3-VL-8B-Instruct）→ 与 transcript 合成统一时间轴 → summarize 可引用/嵌入帧 | 讲义类视频报告包含画面解读与关键帧；纯语音视频不受影响（组件可选） |

S1+S2 = MVP 最小闭环；S3 完成即满足「对接 Agent」目标；S4/S5 按需。

## 7. 风险与预案

| 风险 | 影响 | 预案 |
|---|---|---|
| B站 cookie 续期机制已变（疑似失效） | 字幕链路寿命受 cookie 有效期限制 | S1 内先逆向修复；实在不行做成「到期提醒重新扫码」并主推 ASR 路线（体验几乎无损）——**已按预案后半句执行（D-012）**：不逆向修复，转「登录态失效提醒」 |
| 字幕风控污染升级 | 拿到假字幕 | validate 规则 + 降级姿势（现四条，S2 加标题相关性）；与 ASR 抽样比对的强校验不做（D-015；该漏洞至今无漏网实例） |
| >1h 超长视频 | 云转写 50MB/1h 上限；本地无限制但内存峰值 | 云路线切片；本地 sensevoice 整段、mlx 分段（S1 先支持到 2h 内） |
| B站 412 风控 | 批量时被限 | 请求间隔与退避；批量是 S5 的事，MVP 单条无碍 |
| VRA/BTC 上游演进 | 抽件过时 | 抽件时记录 commit，视为一次性移植，不追上游 |
